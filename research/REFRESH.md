# Cageside Ledger recurring data update

Open this existing owner-private Site from its source credential using the Sites source helper. The source repository is the durable store. Preserve the existing audience, model and journal. The Site is a static projection of these records.

1. Look up the next UFC event that has not started, including the official local date, first bout time, venue and announced matchups on UFC.com. Check official card changes or weigh-ins. Exclude fights that have started. After an event starts, advance to the next announced card. If timing cannot be established, withhold that forecast. If there is no new event, still check for newly published results.
2. Obtain the latest UFCStats mirror CSVs from Greco1899/scrape_ufc_stats. Record upstream blob IDs. Map ufc_event_details.csv to events.csv, ufc_fight_results.csv to greco.csv, ufc_fight_stats.csv to rounds.csv and ufc_fighter_tott.csv to bios.csv. Use GitHub fetch_file to get small UTF-8 files and the SHA for large ones, then fetch_blob by SHA if the content is empty. Write bytes in chunks. The historical odds calibration input is the frozen rfordatascience/tidytuesday data/2026/2026-07-07/ultimate_ufc_dataset.csv (tidy.csv). The seed inputs are gzipped under research/inputs. Decompress to a scratch folder. Use the latest verified histories where available and disclose upstream delays.
3. Match fighter identities and aliases against UFCStats; a missing row is different from a verified debut. Source both sides of one book's current pre-fight moneyline, the quote date/time or observation time, source URL and bookmaker. Use null or empty if unverified. Record new event data in research/event.json and research/card.csv following the included schemas. UTC asOf is the actual observation time. Compare card, odds, source timestamps and history coverage to the saved snapshot. Ignore formatting differences and do not roll the time forward on unchanged market observations. Only change underlying data, never refit or change the eligibility rules.
For every withheld bout, look up the affected fighters. Resolve aliases against UFC athlete profiles and event opponents. Research UFC, Contender Series and Road to UFC histories, regional promotion results and dated opponent records. Cross-check conflicts with a second independent source. Add sourced, pre-event scouting notes for each affected fighter to the current event JSON under scouting, keyed by card name, and set scoutingAsOf. Report promotion, opponent, method, sample size and notice where documented. Leave missing stats unknown. Clear the previous card’s notes on rollover. Do not feed regional-only scouting notes into CL-1.

4. Run python research/model.py INPUT_DIR and python research/journal.py INPUT_DIR. These update the next event, append immutable pre-fight CSVs, deduplicate identical forecasts, and match published results to prior dated pairings. Handle verified withdrawals or cancellations separately as void by recording a sourced settlement and preserving the original snapshot. Scores must only cover issued forecasts on settled decisive bouts. A missing result is pending. If another run updated the repo, reopen its latest revision and rerun against that journal. Never force push.
5. Validate output: correct event date, no same-day/post-fight data, probabilities sum to one, current source links, paired odds or explicit missing values, clean JSON, every journal download exists. Use node --check dist/app.js. For a changed static projection use the established private Sites save-and-deploy path. Verify the returned deployment and journal/readback. If neither prices, results, card nor underlying stats changed, skip the write. Summarize new cards, meaningful opponent or market changes and scored results. If an upstream data source failed, retain the last successful snapshot and report freshness.

CL-1 uses the frozen coefficients and historical score report checked into this repository. The sportsbook comparison covers matched archival quotes only. Never infer promotional or judging intent from the pattern or call a price difference an established advantage.

## Finish forecasts and parlay inputs

For each announced matchup verify scheduled_rounds in card.csv (3 or 5, blank if unknown). Set event.propAsOf to the actual time a new pre-fight prop snapshot is issued. Replace propQuotes for each new card. Record named-fighter KO/TKO/DQ prices under propQuotes.fighterKO where the book’s settlement terms match, and both sides of named-book distance prices by the exact fighter_a|fighter_b pair, with bookmaker, observation time and source URL. If unavailable, leave the pair unpriced. UFCalendar documents consensus markets for methods, distance and totals, with anonymized books; use consensus only as a labeled cross-check when access is available. The community UFCStats API documents round and fighter endpoints and can cross-check history when available. Neither provides a substitute for a named-book quote. Do not put keys in Site data or browser code. Run the same model.py and journal.py commands: they apply frozen Finish-1 coefficients, append the new prop predictions and settle past outcomes. Preserve earlier snapshots, including winner-only CSVs. Highlight new meaningful prop or format changes in the update.

## Connected sources and private deployment

Before model.py, run python research/evidence.py SCRATCH_SOURCE_CACHE. It imports the Bair release, UFC-Almanac, both Kaggle datasets, and the Odds Gap sample, validates their schemas and joins dated observations to the current official pairings. A failed import should retain the last good published evidence, identify its card and age, and be reported. Run model.py to refresh the separate exact-fight-ID closing comparison. Compare source row counts, content and date coverage; only deploy changed evidence. No raw future outcomes or archival close prices enter CL-1 features.

Refresh any private connections through service/refresh_connections.py. Obtain siwc_bypass_bearer_token from get_site for this exact owner-private Site. Pass it once on hidden stdin (stty -echo for a PTY); do not put it in source, arguments, files, logs, or prompts. The Site verifies the runner proof and fetches only previously connected providers. A 'needs key' result is a pending connection, not an outage. A source failure preserves that source’s last successful response. The owner can inspect provider records in Sources.

The Site serves the same dashboard through a Worker now. Before every bundle and publish run python service/build.py and node --check dist/server/index.js after changes to projections or frontend files. The private Worker contains only public evidence and UI assets. Site secrets and encrypted provider credentials stay out of the bundle. Preserve the BUCKET binding and hosted secret settings. Verify a successful native deployment, then request the journal and data from the hosted origin with the same Site-scoped access if reachable.

The Home view and journal include Supplement-1 winner reads on bouts where CL-1 abstains, and fighter-specific plus fight-level submission probabilities. Preserve supplement-v1.json and the separate scoring fields. Identify limited-history reads separately in reports.

Run python research/results_board.py on each refresh, including during the card and before replacing a completed card. Verify finished bout counts against the official results, retain dist/results.json across cards, then rebuild the worker. Recheck the board if a final is corrected.
